**Проблема:**

Бизнес-процесс в банке редко живёт в одной системе. Например, процесс «Выдача кредита» включает шаги в АБС, CRM, антифроде, скоринге, нотификациях — и лишь часть из них исполняется в SberFlow. End-to-End (E2E) мониторинг — это возможность видеть статус, время и результат _каждого_ шага процесса, независимо от того, в какой системе он исполняется. На текущий момент без E2E мониторинга  — SberBPM.Monitor и инструменты мониторинга внешних АС — работают изолированно. Система SberBPM.Monitor отслеживает только шаги, исполняемые непосредственно внутри SberFlow, тогда как значительная часть сквозного процесса  остается вне зоны видимости. Внешние автоматизированные системы не передают метрики в Monitor - нет единой картины исполнения.  В итоге часть E2E-процесса остаётся «слепой зоной», что не позволяет оперативно выявлять отклонения и задержки.

**Влияет на:**

- Бизнес-процессы банка (кросс-системные процессы)
- Системы мониторинга (SberBPM.Monitor);
- Исполнительные системы (SberFlow, Единый коллектор (COTE): Kafka (Corax), REST-сервисы);
- Команды сопровождения (бизнес-уровни);
- DevOps и интеграционные команды, отвечающие за настройку и поддержку мониторинга.

**В результате чего:**

Часть 1. E2E мониторинг (сквозная видимость процесса)

- Внедрение E2E мониторинга позволит видеть статус, время и результат каждого шага процесса вне зависимости от системы исполнения.
- Будет создан единый BPMN-файл, описывающий весь процесс, включая «пустые» шаги для внешних АС.
- Внешние АС начнут отправлять метрики через единый коллектор (единая точка приёма метрик) в Monitor.
- Появится сквозной идентификатор процесса, связывающий все шаги из всех систем.
- Monitor становится единой точкой визуализации всего E2E процесса.

Польза от решения: Повышается надёжность и предсказуемость E2E-процессов.

От E2E мониторинга:

- Устраняются «слепые зоны» — Monitor видит все шаги процесса, включая исполняемые во внешних системах (не детализированы в BPMN Flow).
- Формируется единая картина исполнения сквозного процесса.

**Требования:**

| **Компонент**    | **Роль в E2E мониторинге**                                                                                                                                                                                                            |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Flow Designer    | Единый конструктор BPMN. Владелец модели процесса. Ввод нового типа задачи "Задача внешней АС" ( c ID АС, кодом шага в АС и др параметрами, позволяющим запросить метрики).                                                           |
| Flow Engine      | Исполняет только свои шаги. Генерирует сквозной ID экземпляра процесса (E2E_ID) и ID задачи внешней АС ("пустого шага" на BPMN). Отправляет мета-события (не метрики!) в Kafka для E2E-связки. Вызывает внешнюю АС, передавая E2E_ID. |
| Единый коллектор | Точка приёма метрик от внешних АС. Валидация, трансформация в события для BPMMonitor, совместимые с текущей моделью данных, маршрутизация в BPM.Monitor.                                                                              |
| BPM.Monitor      | Визуализация. Собирает данные из двух источников: от Flow (через Kafka) и от внешних АС (через Единый коллектор телеметрии (COTE)).                                                                                                   |
| Внешние АС       | Отправляют метрики (старта/завершения и др) в Единый коллектор. Никакой другой логики мониторинга не несут.                                                                                                                           |
